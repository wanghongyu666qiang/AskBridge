# Phase 7：设置、容错与隐私

## 目标

在保持 `auto_submit=false`、隔离专用 Chrome 和 D 盘运行数据边界的前提下，把已有配置模型接入完整原生设置页，并完成开机启动、配置恢复、临时文件、日志和人工兜底的产品闭环。

## 实现

- 设置页分为快捷键、供应商、浏览器和常规四页；支持默认/启用供应商、内置入口覆盖、自定义 HTTPS 供应商、快速提示词、浏览器生命周期、开机启动、剪贴板兜底和调试日志。
- 设置保存先校验完整候选配置；开机启动、快捷键注册和配置原子保存构成可回滚事务，任一步失败都恢复旧状态。
- Windows 配置提交使用 `ReplaceFileW` 写穿原子替换；调试日志和 Chrome 路径保存后立即重载，旧浏览器管理器安全重建。
- 浏览器生命周期由 serde 枚举约束；“每次准备后询问关闭”必须在用户确认已完成发送后才正常关闭专用 Chrome。
- 浏览器/CDP 前置失败保留当前请求并进入可重试人工兜底；新的任务使用独立取消令牌，不会复活已取消的旧任务。
- 开机启动只使用当前用户 Run 键；浏览器工具只控制 AskBridge 专用配置并可执行启动、连接检查和打开默认供应商页面。
- 配置继续采用 schema v3 的逐步迁移、损坏文件备份和临时文件原子替换；自定义供应商 ID 和 HTTPS 边界增加日志安全校验。
- 日志写入 `data\logs\askbridge.log`，5 MiB 轮换一次；源代码审计测试禁止敏感字段进入运行时 tracing 调用。
- 临时图片正常路径立即删除；启动清理仅处理超过 24 小时的 `askbridge-*.png`，测试确认不触碰其他文件。
